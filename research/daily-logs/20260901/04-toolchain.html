What SIMMA is actually built from: one novel tool, and a fragmentomics axis with no tool at all

Read straight out of the Methods in mrd/data/papers/2026.04.08.26350410v1.full.pdf. Common backbone for every axis: Guppy v6.5.7 (WGS, super-accurate) or Dorado v7.4.14 (targeted) → minimap2 v2.24 -ax map-ont --MD → GRCh38 or T2T-CHM13v2.0 → mosdepth v0.3.3.

AxisCore toolWhat it is
Copy number / TFCOPYBARA github.com/cortes-ciriano-lab/copybara-cfWritten for this paper — the only genuinely new tool in the stack
ecDNA quantify + trackCOPYBARA-focal — calls ecDNA at absolute CN ≥ 8, BH-FDRWritten for this paper. Threshold is FDR-adjusted P < 0.5 — not 0.05
Methylationmodkit v0.3.2 (summary --only-mapped, pileup --cpg, extract --cpg); v0.5.0 for stats over repeatsOff the shelf (ONT). Satellite classes need the T2T alignment
Fragmentomicssamtools view $bam | cut -f 10 | perl -ne 'print length($_)' + hard-coded size binsNo tool at all. And no filter flag — -F 0x900 is missing, so secondary and supplementary alignments are double-counted
SV / breakpointsSAVANA v1.3.7 tumour-only, 10 kb bins, primed by COPYBARA TF+ploidy, savana classify --cna_rescueOff the shelf
ecDNA assembly + cross-checkhifiasm v0.25.0-r726 -ont; CoRAL v1 and AmpliconArchitect v1.2.2 as corroborationOff the shelf
Modelscikit-learn Random Forest + conformal predictionOff the shelf. Takes 7 feature blocks — copy number, methylation, fragmentomics. No ecDNA or SV block exists
Takeaway: only COPYBARA and COPYBARA-focal are new; everything else is a version pin away from reproducible. ecDNA runs as a parallel track, never as a model feature — the design guardrail being that a signal present in only 65/792 (8.2%) of samples does not belong in a feature column.
